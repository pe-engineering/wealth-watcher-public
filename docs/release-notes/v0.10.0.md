# Wealth Watcher v0.10.0

## Highlights

- Fixes release and container-image publishing after the repository organization transfer. Version-tagged builds now target the `pe-engineering/wealth-watcher-public` repository and publish the API, web, and optional webhook-relay images under the current GHCR namespace.
- Refreshes the release pipeline's build and supply-chain inputs, including pinned Docker base-image digests, CI and Pages actions, and CodeQL actions, while retaining signed images with SBOM and provenance metadata.
- Updates the SnapTrade.Net dependency to `6.0.14` and Vite to `8.2.2`, with the UI lockfile regenerated for the updated dependency graph.

## Fixes

- Prevents the image-publish and GitHub Release jobs from being skipped or publishing to the former `paevans87` namespace after the organization transfer by aligning their repository guards, image names, and OCI source label with `pe-engineering/wealth-watcher-public`.
- Refreshes the pinned .NET SDK/runtime, Node, nginx, and PostgreSQL image digests used by the application and local Compose deployment.
- Keeps the release validation, image publication, signing, SBOM/provenance, and tagged GitHub Release stages aligned with the current repository location.

## Upgrade notes

- No database migration or new application environment setting is introduced by this release (`requiresMigration: false`). Back up PostgreSQL and the configured `CONFIG_PATH` Data Protection key directory before updating as standard operational practice; also back up the relay data directory when webhook delivery history matters.
- Published-image deployments that still reference the former `ghcr.io/paevans87/...` packages must update their image configuration to the current `ghcr.io/pe-engineering/...` namespace. Use the `v0.10.0` tags listed below, or immutable `sha-<full-commit-sha>` tags after the tagged workflow completes. Local-build deployments do not need this registry change.
- Pull and restart the relevant Compose services after updating the image references. Verify access to the new GHCR packages before cutover; the release workflow does not rewrite local `.env` or deployment files.
- Because no schema migration is included, a normal rollback should restore the previous image tags or digests and retain the backup; do not run a destructive database down migration for this release.

## Docker images

- `ghcr.io/pe-engineering/wealth-watcher-public-api:v0.10.0`
- `ghcr.io/pe-engineering/wealth-watcher-public-web:v0.10.0`
- `ghcr.io/pe-engineering/wealth-watcher-public-webhook-relay:v0.10.0`
- The successful tagged workflow also moves the stable `latest` alias, publishes immutable `sha-<full-commit-sha>` tags, and signs the images with SBOM/provenance metadata.
- Image digests are not available until the tagged workflow completes. Record the published digests then when immutable release evidence or deployment pinning is required.

## Known issues

- Deployments using the former GHCR namespace require a manual image-reference update; existing local `.env` files and deployment files are not changed by the release workflow.
- The application remains intended for a local or trusted network and has no built-in authentication, authorization, or tenant isolation. The browser-only public demo continues to use fictional, resettable data and does not connect to the API, database, accounts, relay, or provider integrations.
