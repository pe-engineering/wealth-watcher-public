# Wealth Watcher v0.11.0

## Highlights

- Keeps the public browser demo populated with a rolling 366-day history derived from the current date, including generated rises and falls calibrated to an approximate £400k–£500k net-worth band.
- Rebuilds only generated fixture rows when the date changes, preserving user-added entries, settings, catalogue changes, integrations, and other browser-local demo state across refreshes.
- Refreshes cached and active demo views when the date rolls over or the page regains focus or visibility, so the dashboard, history, calendar, forecast, FIRE, and budget surfaces continue to show current fictional data.
- Adds an accessible collapsible public-demo banner that is expanded by default and stores its preference independently from the Reset demo action.

## Fixes

- Prevents stale or empty-looking browser-demo charts when a visitor returns on a later day or resumes an existing demo session.
- Keeps manual demo entries separate from generated history, so date rebasing does not overwrite user-added values or clamp them into the generated baseline range.
- Adds regression coverage for date-relative fixture generation, manual-entry preservation, value bounds, banner persistence, and responsive layout contracts.

## Upgrade notes

- No database migration, API contract change, or production environment setting is introduced by this release (`requiresMigration: false`, `requiresConfigurationChange: false`). Deploy the application images as normal. Back up PostgreSQL and the configured `CONFIG_PATH` Data Protection key directory before updating as standard operational practice; also back up the relay data directory when webhook delivery history matters.
- Existing browser-only demo state using the previous fixture format is automatically rebased into the current format when the demo loads. Generated rows are refreshed while manual entries and saved demo settings are preserved. The separate collapsed-banner preference is not changed by Reset demo.
- The generated demo baseline is illustrative and targeted to approximately £400k–£500k. User-entered entries are intentionally preserved without clamping and may move the displayed total outside that range.
- For rollback, restore the previous API and web image tags or immutable digests and retain the normal backups. An older application version does not read the new demo storage format, so browser-local changes made after upgrading may not carry back to the older demo version; this does not affect the production database.

## Known issues

- The public demo remains fictional, browser-local, resettable data and does not connect to the API, database, accounts, webhook relay, or provider integrations. Its generated value band is approximate; user-entered values are not constrained.
- The application remains intended for a local or trusted network and has no built-in authentication, authorization, or tenant isolation.
