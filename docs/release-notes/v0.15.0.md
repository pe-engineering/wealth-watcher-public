# Wealth Watcher v0.15.0

## Highlights

- Fixes the Dashboard Day net-worth total, which could differ from the Week, Month, 3 Months, Year To Date, and MAX totals. For categories with a connection set to poll only during market times, the Day total, change, contributors, and asset cards stopped at the market-close chart bucket. Evening balances (for example after-hours pension syncs, manual entries, or webhook updates) were therefore left out until the next day. Every range now reports the same current total from all observations available now. The Day chart still ends at market close.
- Keeps active integrations running after a successful connection test. Re-testing an `Active` connection used to drop it back to `Tested`, which silently stopped scheduled polling and webhook dispatch for that connection.

## Fixes

- Adds a per-category `Current` snapshot to dashboard and aggregate API responses, built from every observation up to now. The dashboard headline, YTD change, contributor pills, FIRE status summary, and asset-group cards and totals now use this snapshot instead of the last chart point.
- Preserves the `Active` status when an already active connection passes a connection test. New connections still advance to `Tested` before discovery and allocation.
- Adds API regression tests that check the dashboard total is identical across every period after a market-close sync, and that the Day total includes evening observations.

## Upgrade notes

- No database migration is required (`requiresMigration: false`) and no environment variable or deployment configuration change is required (`requiresConfigurationChange: false`).
- As with every update, back up PostgreSQL and the configured `CONFIG_PATH` Data Protection key directory first, and back up the relay data directory when webhook delivery history matters.
- Aggregate API responses gain an optional `Current` property. Existing fields are unchanged, so clients that ignore unknown properties need no change.
- Connections that an earlier re-test left in `Tested` are not changed automatically. Check the Integrations page after upgrading and reactivate any connection that should be polling.
- To roll back, restore the previous API and web image tags or immutable digests. There is no schema change to reverse. After a rollback, the Day total again stops at market close for market-hours-only connections.

## Known issues

- Investment history recorded before v0.14.0 keeps only the last observation of each day, so Day-range charts for earlier dates remain flat.
- Wall-clock polling schedules follow the API host's local time and do not offer a separate per-connection time-zone setting.
- The application remains intended for a local or trusted network and has no built-in authentication, authorization, or tenant isolation.
