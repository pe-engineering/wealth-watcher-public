# Wealth Watcher v0.12.0

## Highlights

- Reworks dashboard and asset-card periods around Day, Week, Month, 3 Months, Year To Date, and MAX. Day retains each available hourly observation within the browser-local day and configured market hours, while longer periods use daily aggregation.
- Expands primary asset-card charts across the available desktop card width and uses period-aware representative observations instead of visually joining carried-forward values across longer buckets.
- Shows property value and linked equity as separate chart lines, keeping the two measures visually distinct rather than joining them into one series.
- Promotes linked property equity changes to first-class dashboard growth contributors, so mortgage-driven equity movement can appear alongside property-value and other asset movements in the growth summary.
- Makes the Dashboard FIRE status snapshot collapsible. It starts compact on mobile, remains expanded by default on desktop, and preserves the chosen state during live dashboard refreshes.

## Fixes

- Removes the standalone hourly range while retaining hourly detail where it belongs inside Day, and keeps legacy period requests compatible with the revised aggregation model.
- Aligns chart tooltips, browser-demo responses, and dashboard summaries with the displayed aggregate points and browser timezone.
- Derives provider-linked aggregation from external values and value-source relationships, avoiding reliance on obsolete provider-key fields.
- Adds regression coverage for hourly Day buckets, longer-range daily buckets, property value/equity series, equity contributor attribution, responsive FIRE-card behavior, and browser-demo parity.

## Upgrade notes

- No database migration, persisted-data rewrite, API configuration change, or new environment setting is introduced (`requiresMigration: false`, `requiresConfigurationChange: false`). Existing asset and property history is read through the revised aggregation logic without a conversion step.
- Back up PostgreSQL and the configured `CONFIG_PATH` Data Protection key directory before updating as standard operational practice; also back up the relay data directory when webhook delivery history matters.
- Existing market-hours settings affect which intraday observations appear in Day. Week, Month, 3 Months, Year To Date, and MAX continue to use daily points.
- For rollback, restore the previous API and web image tags or immutable digests and retain the normal backups. No release-specific data downgrade is required.

## Known issues

- Day can display only the observations available within the current browser-local day and configured market hours; sparse polling history therefore produces fewer hourly points rather than invented values.
- The application remains intended for a local or trusted network and has no built-in authentication, authorization, or tenant isolation.
