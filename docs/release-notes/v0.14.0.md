# Wealth Watcher v0.14.0

## Highlights

- Keeps every hourly integration poll in history. Each scheduled observation is now stored at its own date and time instead of overwriting the earlier value from the same day, so Day-range investment charts show intraday movement as new polls arrive.
- Corrects the Dashboard Day headline. The net-worth total and change now sum the same per-category baselines as the asset cards, so categories that start at different hours (for example, cash at midnight and investments at market open) are no longer left out of the headline delta.
- Restores pension creation from the Dashboard and Settings.

## Fixes

- Fixes pension asset creation by resolving the selected asset type correctly in the asset catalogue, and sends new-entry values, mortgages, and invested capital to the API as numbers rather than strings.
- Matches integration history by observation date and time when a replaced connection adopts orphaned history, so replacing a connection updates the matching observation instead of collapsing a day's observations.
- Fixes the API container build: the runtime image now installs the current patched `libgssapi-krb5-2` from Ubuntu instead of an exact package version that Ubuntu had withdrawn.
- Makes the forecast monthly-contribution regression test independent of the calendar date it runs on.
- Refreshes runtime and build dependencies: the .NET 10 SDK and ASP.NET runtime base images (runtime 10.0.12), Node 26 and nginx Alpine base images, the PostgreSQL 18 Alpine Compose image digest, Vite 8.3.4, SnapTrade.Net 6.0.36, Swashbuckle.AspNetCore 10.3.0, SharpCompress 0.50.5, the .NET test SDK and xUnit runner, and the pinned GitHub Actions.

## Upgrade notes

- No database migration is required (`requiresMigration: false`) and no environment variable or deployment configuration change is required (`requiresConfigurationChange: false`).
- As with every update, back up PostgreSQL and the configured `CONFIG_PATH` Data Protection key directory first, and back up the relay data directory when webhook delivery history matters.
- Hourly observations that earlier versions overwrote cannot be reconstructed. Day-range charts gain detail only from polls made after the update. Connections polled more than once a day now store one value entry per observation, so expect the database to grow modestly faster for frequently polled connections.
- The Compose `db` service moves to a refreshed `postgres:18-alpine` digest within the same PostgreSQL 18 major version. No dump and restore is required.
- Swashbuckle.AspNetCore 10.3.0 changes how nullable schemas are represented in the generated OpenAPI document. Application behaviour is unchanged, but regenerate any client you generate from the Swagger document and review nullability differences.
- To roll back, restore the previous API and web image tags or immutable digests. There is no schema change to reverse. Hourly observations recorded by v0.14.0 remain in history after a rollback, and the earlier version resumes updating a single same-day observation per integration value.

## Known issues

- Investment history recorded before this release keeps only the last observation of each day, so Day-range charts for earlier dates remain flat.
- Wall-clock polling schedules follow the API host's local time and do not offer a separate per-connection time-zone setting.
- The application remains intended for a local or trusted network and has no built-in authentication, authorization, or tenant isolation.
